# Weather and market widgets

The VPS now provides the three original JSON routes: /api/prices.php, /api/prices-history.php and /api/weather-prayer.php. No shared-host request or Gemini call is used. Nginx sends these routes to a separate read-only Node container on localhost:18088, so research SQL cannot block widget delivery. The main research HTTP service also supports these routes for the private preview.

Market data comes directly from the same TGJU public summary-table endpoint used by the original PHP files. These are last reported daily closes, not real-time ticks. Each item preserves the instrument's unit, source date, source link and retrieval time. Provider low/high markers determine the sign of changes; the original PHP discarded negative direction. Old source records (over seven days) are visibly marked, even after a fresh download. Missing instruments are listed under unavailable and are never filled with invented values. The current source does not return the old price_tether_irt key. Historical price charts use actual chronological source rows.

Weather comes from Open-Meteo current model data for the five original cities, with visible attribution, source observation time and the explicit Asia/Tehran timezone. Persian weather labels follow WMO codes. Since the previous prayer provider's TLS certificate is expired, calculated prayer times come from AlAdhan method 7 (Institute of Geophysics, University of Tehran). Date, method and timezone are validated, Fajr is used rather than Imsak, and the UI labels these times as calculated.

Caches: market/history five minutes; weather 30 minutes; prayer calculations six hours with a separate key per Tehran calendar date. Failures may serve labelled cached market values for up to 24 hours or weather for up to two hours; previous-day prayer calculations are never reused. A one-minute failure cooldown and single-flight requests prevent retry storms. Persistent atomic cache files are in /opt/zohurnews/data/widgets. Upstream requests use TLS validation, ten-second timeouts, response size limits and fixed provider allowlists; client parameters cannot select arbitrary URLs.

Validation: node --test research/widgets.test.mjs plus existing quota and research tests. Check actual data for at least two cities, live route responses, daily-source dates and units, historical chart points, invalid inputs, and fallback behaviour. Browser QA verifies the public homepage, city switching and price chart.

Deployment: build zohurnews-research:3.5.0, create the widgets cache directory owned by UID 1000, deploy research and widgets services from research.compose.yml, and install the three exact Nginx widget locations while retaining the existing TLS certificate blocks. Preserve the previous stable release and live Nginx configuration. Rollback restores those source/configuration files and the previous research web image; ingestion stays on its quota-controlled 3.4.0 image and its schedule is unaffected.
