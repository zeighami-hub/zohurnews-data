# Academic research module 1.0 / release 3.11.0

This module uses the existing Node research server, central archive queries, trail/dossier service, DejaVu PDF environment and safe spreadsheet conventions. It is not a separate service and does not write news or translations to the central archive. User registration is public; there is no separate administrator panel. Every account can create its own projects and access all research functions. Adding a registered colleague by username grants the same project functions. Nonmembers cannot access private projects.

## Observed baseline and design

The live archive contained approximately 287,000 articles at inspection. Search, source/date/category/tag filters, article dossiers, cross-source suggestions and real XLSX/PDF exports were active. Research coding notes existed only in a browser; server-backed projects, sampling, codebooks and independent-coder sessions did not exist. Existing pages/preferences/exports are preserved.

`academic.sqlite` sits beside `research.sqlite` and `news.sqlite` in `/opt/zohurnews/data`. Schema is additive in this new database only: users, hashed sessions, projects, memberships, frozen items and observed versions, codebooks, sample runs, coding batches, coder records, adjudications, expert reviews, imported AI suggestions and audit events. No destructive delete endpoint exists. Codebooks are immutable versions; edits always append a draft. Approved versions are required for coding assignments. Each sample stores its sorted eligible frame and snapshot hashes, excluded items/reasons, seed, allocation, selected IDs and algorithm version. Captured snapshots never change when the source archive changes; checking creates a separate observed version and explicitly checks only the central archive, not the publisher's live availability.

The first suggested project and draft codebook cover repetition, evaluative co-occurrence and framing. Operational definitions and examples require researcher review and explicit approval. These are content indicators, not proof of psychological effects. No unattended AI analysis runs and no additional Gemini quota is consumed. External AI suggestions may be imported with model/version/prompt/time/uncertainty and exact validated text offsets; they remain a separate dataset and never enter human reliability statistics. Evidence offsets are JavaScript UTF-16 half-open character ranges within a named snapshot field.

## HTTP/UI

The desk links to `/academic.html`, with eight Persian RTL tabs: projects, dataset, sampling, codebook, coding, validity/reliability, analysis and exports. Static assets: academic.html, academic.css, academic.mjs. Displayed project/tab preferences use localStorage namespace `zohurnews.academic.v1`; primary research data is on the server. Pending unsent coding edits use a separate per-user/batch/item recovery key and cannot overwrite a newer server revision.

All APIs are under `/api/academic/`. Public: GET session, POST register/login. Authenticated: POST logout, GET/POST projects. Project scoped `/projects/:id/:resource`: project, copy, members, items/item, add-articles, manual, check, duplicates, samples/sample, codebooks/codebook, approve-codebook, batches, assign, codes/code, release, reliability, adjudicate, analysis, experts/expert, suggestions/suggestion, audit, export. GET reads; POST mutates JSON with session CSRF header. Mutation Origin must match Host. HttpOnly, Secure, SameSite=Strict cookies expire after 12 hours; session tokens are hashed at rest. Passwords use scrypt and salts, minimum 12 characters. There is no public bootstrap or role escalation endpoint. Login and registration have bounded in-memory throttles in addition to nginx rate limits.

Each collaborator has full research functions, but the independent coding rule is enforced across code APIs, audit and exports: other coders' data is hidden until **all** assigned records are confirmed and the batch is explicitly released. Initial confirmed records are locked. Revisions require a new independent batch. Adjudication never overwrites initial ratings. Reliability is calculated from initial ratings, not adjudicated outcomes. Analysis resolves unanimous human ratings or explicit adjudication; unresolved/missing entries remain missing and expose witness IDs and publisher links. Programmatically submitted research text is never executed; evidence must exactly match the immutable text. URL import is metadata and researcher-supplied permitted text, not automatic crawling (avoids SSRF and silently claiming full text).

## Supported methods and limits

Census, simple seeded random, proportional stratified source/day, systematic with seeded start and stable ID order, and criterion-recorded purposive sampling are implemented. SHA-256 ranking is deterministic; proportional strata use largest-remainder allocation and may give zero sample to small strata, which is disclosed in allocations. No title-similarity removal occurs. Same URL, identical normalized stored text and researcher-assigned event identifiers are distinct, unverified relation suggestions. Rewrite/independent narrative labels are human decisions, with recorded reasons.

Krippendorff alpha supports **nominal and interval** variables and pairable missing data; pairwise agreement is also reported. Undefined constant distributions, insufficient pairable units and unsupported ordinal/ratio levels return null with reason. No confidence interval or automatic validity certification is claimed. Reference: Klaus Krippendorff, *Computing Krippendorff's Alpha-Reliability* (2011, updated 2013), University of Pennsylvania: https://www.asc.upenn.edu/sites/default/files/2021-03/Computing%20Krippendorff%27s%20Alpha-Reliability.pdf . The published binary example alpha 0.095238 is a regression fixture.

Initial operational bounds are 50 projects per account and 5,000 captured records / 50 MiB per project, 512 KB per snapshot, with at most 500 additions per request and 20 coders per batch. Research writes stop below 512 MiB free disk space. Dataset UI displays up to 200 filtered rows; exports retain all permitted project records. PDF tables explicitly disclose a 200-row cap; large PDF reports must be split by section. Renderer: one request at a time, 45-second process timeout, 64 MiB output bound. XLSX strings are forced to text to prevent formulas; PDF escapes content and denies remote resources. JSON/ZIP preserve longer raw fields that spreadsheet cells cannot represent in full. The existing XLSX clean helper limits cells to 32,700 characters, so JSON is the authoritative full snapshot export.

Exports: XLSX, Persian PDF, UTF-8 quoted CSV, SPSS Syntax, JSON and reproducibility ZIP. CSV has one row per item/coder/batch for one codebook version. Baseline columns are item_id, article_id, source_id, news_url, title, coder_id, batch_id, book_ver, coding_status; variables are prefixed `v_`. Categorical values have numeric labels; strings in CSV are capped at 32,767 UTF-8 bytes for SPSS (full text stays in JSON); numeric missing values are blank/SYSMIS; text missing values are empty strings; zero remains valid. ZIP contains each codebook version separately, original snapshots, source URLs, books, sampling frames and visible coding records. SPSS is not installed on the host: Syntax is structure-tested, not executed in IBM SPSS; no native SAV is claimed. Statistical use must account for multiple coder/round rows rather than treating them as independent news cases.

## Backup and recovery

Before changes, complete source and nginx configuration plus verified online backups of both existing SQLite databases were saved to `/opt/zohurnews/backups/academic-before-20261108T150306Z`. Each SQLite snapshot passed integrity_check before compression, with sizes and SHA-256 recorded in manifest.json. Existing browser preferences were never rewritten.

The scheduled local backup includes academic.sqlite automatically when present. Encrypted offsite backup manifests accept both old two-database and new three-database snapshots. Old snapshots remain valid. Academic database contains private project data, password hashes and sessions; never commit or publish it to GitHub. Code only is committed. Offsite's existing 6 GiB free-space guard is retained; a successful offsite upload must be confirmed separately, rather than inferred from code compatibility. Offline/tray consumers must tolerate the optional academic file.

For rollback, restore the pre-change source/compose, start the former research image and retain academic.sqlite untouched; archive and translation worker need no rollback migration. For full data restore, decompress backups into a separate staging directory, verify integrity and manifest hashes, stop only affected research services, preserve current database files and WALs in a recovery directory, then restore consistent SQLite snapshots. Never copy a running SQLite main file without online backup/WAL handling.

## Verification

Run `node --test research/*.test.mjs`; `python3 -m unittest discover -s research -p 'test_*.py'` in the application image. Dedicated tests cover public self-registration/own project permissions, CSRF and outsider rejection, immutable snapshots and source-version detection, replayable seeds/strata, reasoned exclusions, codebook version isolation, sealed coding through APIs/audit/exports, release gating, adjudication, published alpha example, password/session checks and database reopen persistence. The isolated academic-ui-test-server and academic.e2e.cjs exercise the eight-tab workflow without creating test records in production. Real archive integration/export checks use a separate temporary academic database.

Verified results before activation: all 25 research Node tests, 10 ingestion Node tests and 14 research Python tests passed in the application container. Browser E2E passed account registration, own project creation, colleague membership, capture, census, codebook editing/approval, independent coding in two browser contexts, alpha=1, analysis, reload persistence and source access. A read-only real-archive integration imported 4 real records into a temporary academic database, recorded 1 exclusion, drew a 3-item seeded stratified sample, confirmed two coders and produced all 6 output formats. These coding values are test fixtures, not substantive research findings. No test account or fixture project is installed into production.
